## v0.2.0-hotfix — downloads are no longer destroyed by a SHA-1 mismatch

**Fixed:** a completed download was deleted when its SHA-1 did not match Sony's metadata, so users never received the update. This reproduced live: for `PCSA00007` the file Sony serves is exactly the declared size (13,977,360 bytes) but hashes `2da63c02…`, while Sony's own update XML claims `sha1sum = 25e00e3c…` — that metadata can describe an older revision of the same `.pkg` path. A mismatch is therefore not always corruption.

### What changed
- **A completed download is kept** and reported as *saved but unverified*; the activity line now shows the actual file hash instead of failing the package.
- **Hashing reads the file back from disk**, so no stream/encoding difference can cause a false mismatch.
- **One automatic retry** before a mismatch is trusted.
- **Truly failed downloads are still discarded**: no data received, fewer bytes than Sony actually served, or a network error. Oversize data is still rejected.
- **`strict=True`** (API/source use) restores the old raise-on-mismatch behavior for anyone who wants the hard guarantee.

### Behaviour summary
| Case | Before | Now |
|---|---|---|
| SHA-1 matches | verified | verified (unchanged) |
| SHA-1 mismatch, complete file | deleted, error | **kept**, warned, installable in Vita3K |
| Truncated / no data / network error | deleted | deleted (unchanged) |

### Tests
Automated suite: **19/19 passing** in CI, including new regression tests that reproduce the mismatch scenario (file survives), strict mode, verified path, truncated-download cleanup, and retry-then-report. Packaged executable startup check also runs on this tag.

### Download
`vita-pulse.exe` + `SHA256SUMS.txt` (verify SHA-256 against the sums file). No Python required.
